## 1. 优先级最高的确定问题

### P0：章节标题入场结束后未归位

位置：[`global.css:6572`](../src/styles/global.css#L6572)、[`global.css:6596`](../src/styles/global.css#L6596)、[`PostLayout.astro:2589`](../src/layouts/PostLayout.astro#L2589)。

基础完成态 `.prose .pr.is-in` 设置 `translate3d(0,0,0)`，但后面的 heading/subheading 规则以相同选择器权重分别设置 `-18px`、`-14px`，覆盖了完成态。浏览器在等待动画完成后实测：

| 元素 | 完成态 class | 实际 transform | 应有状态 |
|---|---|---|---|
| H2 | `pr is-in` | `matrix(1, 0, 0, 1, -18, 0)` | 位移归零 |
| H3 | `pr is-in` | `matrix(1, 0, 0, 1, -14, 0)` | 位移归零 |

另核对了 `PostLayout` 中标题定位反馈的 `transition`：首次采样时标题尚未进入 `.is-in`，只显示颜色/阴影过渡；入场后的采样具有 opacity/transform 过渡。该差异属于不同状态，本次不将其列为已确认冲突。

建议：

1. 为 heading/subheading 写明专属 `.is-in` 完成态，或把位移初始态严格限定为 `:not(.is-in)`。
2. 后续统一参数时集中管理标题的 transition 属性列表，明确入场与定位脉冲各自控制的属性。
3. 验收使用浏览器 computed style：H2/H3 动画完成时平移均为 0，opacity 为 1；直达、客户端跳转、锚点进入均一致。

### P1：900ms 的正文动画仍然“很快”，主因是曲线前段过陡

位置：[`global.css:6577`](../src/styles/global.css#L6577)、[`BaseLayout.astro:733`](../src/layouts/BaseLayout.astro#L733)、[`PostLayout.astro:395`](../src/layouts/PostLayout.astro#L395)。

正文主曲线为 `cubic-bezier(0.16, 1, 0.3, 1)`。数值计算表明：

| 动画进度 | 当前曲线已经完成的位移 |
|---|---:|
| 25% 的时间 | 82.6% |
| 50% 的时间 | 97.2% |

因此，900ms 动画约在前 225ms 就走完大部分路程，后面主要是很难察觉的尾速。380ms 抽屉约在前 95ms 就完成同样比例的位移，移动端约 82vh 的大面板尤其显得冲。

建议先改曲线与幅度：正文采用 `cubic-bezier(0.25, 0.1, 0.25, 1)`，位移 6–10px；面板空间变化采用 `cubic-bezier(0.4, 0, 0.2, 1)`。不要把所有 900ms 改成 1200ms。新曲线需要视觉复核，以下时长是初始调校值。

### P1：滚动回看反复淡入，影响长文定位

位置：[`PostLayout.astro:844`](../src/layouts/PostLayout.astro#L844)、[`PostLayout.astro:896`](../src/layouts/PostLayout.astro#L896)、[`PostLayout.astro:994`](../src/layouts/PostLayout.astro#L994)。

当前 resetObserver 会把落到视口下方 120px 以外的已读块移除 `.is-in`，再下滚时重播；页首标题和日期也会在返回顶部时重播。

浏览器复现：同一段落经历 `pr is-in → pr → pr is-in`；第二次进入后约 80ms，opacity 仍约 0.41，平移约 12.55px。这是往返阅读时真实存在的视觉变化，不是首次加载。

建议：正文与页首标题默认每次路由进入只播一次，回看保持稳定。保留首次出现的轻淡入；锚点跳转、浏览器返回恢复位置、快速滚动到达的内容直接可读。装饰线条可保留一次绘制，正文列表和表格不逐行重新排队。

## 2. 各条交互链的修改方案

### 进入文章：把多段演出收敛为一个连续交接

位置：[`PostTransition.astro:269`](../src/components/PostTransition.astro#L269)、[`PostTransition.astro:348`](../src/components/PostTransition.astro#L348)、[`PostLayout.astro:789`](../src/layouts/PostLayout.astro#L789)、[`PostLayout.astro:608`](../src/layouts/PostLayout.astro#L608)。

当前流程：墨晕覆盖 220ms → 页面交换 → 墨晕退去 280ms → 标题逐字 500ms、错峰最多约 340ms → 停顿 180ms → 标题从中心缩回 620ms → 侧栏、简介、正文容器与正文块分别入场。桌面标题放大为 1.25 倍。

完整本地检查中，桌面标题独立舞台持续约 1.64 秒，移动端约 1.68 秒；从归档出现转场遮罩到文章解除 hold 约 2.27 秒。后者包含本地页面加载，不能作为线上速度结论。可确认的是，前段墨晕很急，后段标题却占据较长独占时间。

还有一处时序误解：退场判断 `state.p >= 0.75` 使用经过 `power2.out` 缓动后的值；它在 280ms 动画约 104ms 时就可达到，并非注释所写约 200ms。若要保证实际交接时间，应使用时间线位置或未缓动时间进度。

推荐默认方案：

- 保留水墨识别，但减弱墨点扩张幅度；覆盖 280–320ms、揭开 320–380ms，与新页头部淡入部分重叠。
- 标题在最终位置显现，约 650–750ms；分词错峰总量控制在 100–160ms。简介和日期一起出现，日期不再另外打字。
- 正文容器与内部块只保留一层位移；标题显现不作为正文阅读、导航操作的前置锁定条件。
- 浏览器前进后退、带 hash 的章节链接与回到页首不播放独占标题舞台。

如果希望保留居中标题的仪式感，可只在会话内首次阅读使用，缩放降至 1.03–1.06，总编排约 1.0–1.2 秒；后续文章使用上述默认方案。需要同步调整 PostTransition、PostLayout、BaseLayout 的 hold/release 协议，不能仅删除某个定时器。

### 滚动阅读：统一正文运动方向，减少内容层级竞争

位置：[`global.css:6596`](../src/styles/global.css#L6596)、[`global.css:6696`](../src/styles/global.css#L6696)、[`global.css:6736`](../src/styles/global.css#L6736)。

当前正文向上浮、标题向右滑、列表/表格逐行横移、引用引号带弹性回弹。列表每项延后 40ms，最多 320ms；表格每行 45ms，最多 540ms，再叠加 800–900ms 过渡。代码、图片和 Mermaid 则使用 650ms。

建议：

- 段落、标题、代码、图片、图表共享轻微上移或纯淡入；章节区分依靠分隔线，而非不同飞入方向。
- 表格和长列表整体出现；确需错峰时最多前三项、总错峰不超过 100–120ms。
- 引号和阅读脊线墨点使用无过冲曲线；保留其强调色，取消放大后弹回。
- 内容较长或已部分进入视口的块直接展示；提前约 40–80px 触发首次淡入，快速滚动时直接完成，防止文字进入阅读区后仍透明。

### 目录与长代码：按距离变化，取消开合时的附加位移

位置：[`PostLayout.astro:1387`](../src/layouts/PostLayout.astro#L1387)、[`PostLayout.astro:1448`](../src/layouts/PostLayout.astro#L1448)、[`PostLayout.astro:1752`](../src/layouts/PostLayout.astro#L1752)。

目录实测展开 450ms、收起 420ms，都是快速起步曲线，并同时改变高度、透明度和 ±6px 位移；箭头单独用 380ms。长代码无论高度差多少，都固定展开 380ms、收起 340ms。

建议：目录只改变高度，内容做轻淡入；箭头跟随同一节拍。高度动画按差值选 360–520ms，长代码上限可到 600ms。连续点击从当前可见尺寸反向，不先重置到原尺寸。结束后统一刷新 Lenis/ScrollTrigger，并保持点击处或当前阅读段落的视觉位置。章节定位的强调反馈在滚动到达后触发，避免现在“点击时已开始脉冲、到达时快结束”。

### 笔记 / 墨问 / 全屏并排：保持外壳连续，内容少动

位置：[`ArticleSelectionDock.astro:3885`](../src/components/ArticleSelectionDock.astro#L3885)、[`InkAsk.astro:3227`](../src/components/InkAsk.astro#L3227)、[`CompanionLayout.astro:328`](../src/components/CompanionLayout.astro#L328)、[`CompanionLayout.astro:405`](../src/components/CompanionLayout.astro#L405)、[`Header.astro:1228`](../src/components/Header.astro#L1228)。

桌面笔记抽屉实际为位移 380ms、透明度 260ms，正文避让最终由 Header 中的 420ms 样式生效。移动面板沿整个自身高度移动，仍只用 380ms。同一操作存在数个独立节拍。

面板互切还包含 ±28px 位移、24% 裁剪、4px 模糊，耗时约 340–388ms。全屏/并排切换先改变布局尺寸，再以部分中心点位移和轻缩放补间；它没有完整保留旧矩形的宽高比例，存在“框先变大，内容再晃一下”的风险。这一项来自实现分析，尚未进行完整切换录制。

建议：

- 桌面抽屉及正文避让共用 480–520ms 和空间曲线；移动底部面板约 500–560ms，并保留手势直接跟随。
- 笔记/墨问 tab 切换保持外框位置和尺寸，内部仅 220–280ms 淡入，至多 4px 位移；删除整块裁剪和文字模糊。
- 全屏与并排统一 520–600ms：捕获前后矩形并完整补间，或使用独立外壳过渡。避免对大量文字长时间缩放造成模糊。
- 把可见状态、惯性滚动、正文宽度避让纳入同一个完成/取消协议。快速开关或更换模式应从当前位置续接。

### 搜索、划词和跨面板反馈：按任务重量分配时长

位置：[`ArticleSearch.astro:1441`](../src/components/ArticleSearch.astro#L1441)、[`ArticleSelectionDock.astro:1255`](../src/components/ArticleSelectionDock.astro#L1255)、[`PinWorkbench.astro:609`](../src/components/PinWorkbench.astro#L609)。

搜索小胶囊入场 680ms、退出 560ms，并叠加缩放和模糊；笔记/墨问大抽屉却只用 380ms。划词飞入为 380ms，对照工作台同类飞行为 800ms，再有 500ms 数字徽标回弹。并非每项都过快，而是重量与节奏不匹配。

建议：搜索入场 280–320ms、退出 180–240ms，输入焦点仍即时可用；减少到 6–8px 位移，去掉 blur。划词托盘 200–240ms，强调操作响应。跨面板飞行共用路径工具，根据距离使用 420–600ms；数据保存立即完成，飞行只负责解释去向。完成反馈只保留一个落点高亮/勾选，避免飞墨、数字弹跳和 toast 同时争抢注意力。

搜索退出当前依赖 580ms 定时器隐藏，调整 CSS 时必须一起处理。优先监听 animationend/WAAPI finished，并保留取消与兜底处理。

### 图片与 Mermaid 查看器：减短清晰化拖尾

位置：[`BaseLayout.astro:2448`](../src/layouts/BaseLayout.astro#L2448)、[`BaseLayout.astro:2557`](../src/layouts/BaseLayout.astro#L2557)。

代码中图片/图表查看器存在 850ms 外壳移动和 1100ms 去模糊，关闭约 550ms；与小面板形成明显节奏差异。

建议保留从原图展开的空间关联，外壳 520–600ms、关闭 360–420ms；去模糊取消或在 160ms 内完成，保证图片文字尽早清晰。连续切图 180–240ms 交叉淡入，无需每张重新缩放。需覆盖 GSAP 与 WAAPI 两条实现路径。

## 3. 推荐的统一参数起点

| 场景 | 建议时长 | 幅度/特征 | 缓动 |
|---|---:|---|---|
| 按下反馈 | 100–140ms | scale ≥ 0.98 | 简短 ease-out |
| hover / 色彩反馈 | 180–220ms | 位移 ≤ 1–2px | `cubic-bezier(.25,.1,.25,1)` |
| 小浮层 / tab | 220–320ms | 位移 ≤ 8px，不模糊 | 同上 |
| 正文首次显现 | 550–650ms | 上移 6–10px，仅一次 | 同上 |
| 目录 / 代码高度 | 360–600ms | 随高度差调整 | `cubic-bezier(.4,0,.2,1)` |
| 抽屉 / 布局切换 | 480–600ms | 同步容器与正文避让 | 同上 |
| 跨面板飞行 | 420–600ms | 随距离调整，弱化弧度 | 同上 |
| 标题原位首次显现 | 650–750ms | 轻错峰，不阻断正文 | `cubic-bezier(.25,.1,.25,1)` |

落地时新增语义参数，例如 `feedback`、`popover`、`contentReveal`、`panelMove`、`transfer`；CSS 与 GSAP/WAAPI 从同一配置派生，避免三份数值分别维护。推荐增加 `src/utils/motion.ts` 或等价共享模块，由它管理 JS 参数并同步 CSS 自定义属性。第一轮只迁移文章及其工具链，验证后再逐页扩展，避免直接改全局 `--ease` 影响首页、归档、图库等已有效果。

退出通常比进入短约 15%–25%；直接拖拽不加缓动；减少动态效果时立即进入终态，保留必要的颜色反馈。保留已有水墨线条、字体与主题特色，把弹性/粒子限制在少量明确的操作成功提示中。

## 4. 实施顺序与验收

1. **先修正确性**：标题完成态与重复播放；确认所有内容可读且归位。
2. **再调阅读主流程**：标题交接、正文曲线、目录/代码开合；以长文反复查阅为主要验收场景。
3. **最后统一工具链**：抽屉与正文同步、tab/全屏/并排、搜索、跨面板反馈、图片查看器。

每批至少检查：

- 桌面、窄桌面和移动端；浅色、深色、绿粉主题与当前字体模式。
- 冷加载、从归档进入、文章切文章、带 hash 链接、浏览器前进后退。
- 往返滚动时已读内容保持可见；H2/H3 完成态位移为 0。
- 快速重复开合目录、代码、抽屉、全屏/并排：无尺寸跳变、闪白或遗留透明态。
- 减少动态效果时无锁滚残留；首次正文直接可读；交互不等待装饰完成。
- 录制关键流程检查峰值速度、同时运动的层数与掉帧。此次未做性能录制，不将观感问题直接归因于硬件性能。

现有测试中有大量源码字符串断言，并把旧设计作为要求，例如 `post-reveal-smooth-scroll.test.mjs` 固定 900ms 和重播行为、`post-title-centering-and-fullscreen-hold.test.mjs` 固定 1.25 倍独占标题。实施新方案时应同步更新这些要求，并补充有意义的浏览器终态/中断验证，不能为了满足旧参数而保留体验问题。相关动效文档也已落后于代码：旧文档仍描述代码块裁剪扫描、图片圆形揭示，而当前已改为 transform/opacity，需要一并校正。
